# Отчёт: Разведчик валют и криптоактивов

## 1. Назначение и бизнес-ценность платформы

«Разведчик валют и криптоактивов» — платформа сбора данных из публичных API с витриной и ответами на вопросы по собранным данным.

Аналитику, финансисту или трейдеру регулярно нужны таблицы котировок: топ криптовалют, цены выбранных монет, история цены, котировки валют к рублю. Вручную на это уходит около 10 минут на операцию: открыть сайт, отфильтровать, скопировать, очистить, свести в таблицу.

Платформа принимает запрос на русском языке, строит план и собирает данные из бесплатных публичных API (CoinGecko, exchangerate.host). Данные сохраняются в едином формате и выгружаются в JSON или CSV примерно за 1 минуту. Каждая операция фиксируется в журнале аудита. Сомнительные запросы автоматически не исполняются: они блокируются подсистемой безопасности Guardrails с фиксацией инцидента.

## 2. Сценарии пользователя

1. **Ежедневный срез рынка.** Набор «Топ-10 криптовалют», запрос «Собери топ-10 криптовалют по капитализации в долларах и сохрани поля: rank, name, symbol, price, change_24h». Действия: «Спланировать» → «Собрать» → «Скачать CSV». Результат: 10 записей с выбранными полями.
2. **Котировки для расчётов.** Набор «Котировки валют к рублю» (exchangerate.host), запрос «Собери котировки доллара, евро и тенге к рублю на дату 2026-09-01». Результат: 3 записи с котировками на дату.
3. **Неоднозначный запрос.** Запрос «Собери самое важное». Результат: Guardrails блокирует сбор, панель показывает причину и рекомендации, кнопка «Собрать» заблокирована, инцидент записан в аудит.

## 3. Точки доступа API

| Метод | Путь | Вход → выход |
| --- | --- | --- |
| POST | `/datasets` | `{name, source}` → `{status, dataset_id}`; 400 при пустых полях, 422 при неизвестном источнике |
| POST | `/ai/plan_and_collect` | `{query}` → `{plan_steps, api_url, fields_to_keep, confidence, needs_review, reason, hints}` |
| POST | `/datasets/{id}/collect` | `{query}` → `{status, records_saved}`; 404, 422 (блокировка Guardrails), 502/504/500 с записью в аудит |
| GET | `/datasets/{id}/records?limit=` | записи с `created_at`, `dataset_id`, `record_json` |
| GET | `/datasets/{id}/export?format=json\|csv` | файл выгрузки |
| POST | `/datasets/{id}/ask` | `{question}` → ответ со ссылками на записи |
| GET | `/audit/runs`, `/audit/summary`, `/agent_runs` | журнал, сводка, решения ИИ |

## 4. Схема данных

- `datasets(id, created_at, name, source)`
- `records(id, created_at, dataset_id → datasets.id, record_json)`
- `agent_runs(id, created_at, query, plan_json, needs_review, error)`
- `audit_runs(id, created_at, action, input, output, status, error, duration_ms)`

Хранилище — SQLite: в Docker это том `market-data` (`/app/data/market.db`), при локальном запуске — `data/market.db`. На поля наложены CHECK-ограничения (`status ∈ ok|needs_review|error`, `needs_review ∈ 0|1`), добавлены индексы по `dataset_id` и `created_at`.

## 5. ИИ-операция

Модель: gpt-4o-mini через ProxyAPI, `response_format = json_object`.

**Схема JSON** (`PlanContract`, pydantic, `strict=True`):

```json
{
  "plan_steps": ["строка", "... от 1 до 5"],
  "api_url": "строка",
  "fields_to_keep": ["строка"],
  "confidence": "high | medium | low",
  "needs_review": true,
  "reason": "строка"
}
```

**Температура:** 0.2.

**Разделение ролей:**

- политика качества (детерминированный код) разбирает запрос и строит `api_url` и `fields_to_keep` только из белого списка;
- модель формулирует шаги плана и оценивает запрос, но может только ужесточить решение.

**Условия блокировки Guardrails** (`needs_review = true`):

- `confidence = low`;
- запрос двусмысленный: нет объекта или ограничений;
- запрос невыполнимый: закрытые данные, прогноз, рекомендации, нарушены лимиты источника, дата в будущем;
- запрос не соответствует источнику набора;
- модель нарушила JSON-контракт.

При блокировке сбор не выполняется, причина пишется в `agent_runs.error` и `audit_runs.error`, а панель показывает блоки «Почему» и «Что сделать».

## 6. Память и контекст

- План сохраняется в `agent_runs`. Сбор повторно использует план для того же запроса и источника, если он построен не более 15 минут назад, и не вызывает модель ещё раз.
- `/datasets/{id}/ask` передаёт модели до 50 последних записей набора. Ответ принимается только со ссылками на существующие `record_id`.

## 7. Контроль качества

**Вход:**

- обязательные поля и длина (`name`, `source` — до 200 символов, `query` и `question` — до 1000);
- источник из списка;
- `limit` от 1 до 500.

**Выход:**

- строгие контракты pydantic для ответов модели (`PlanContract`, `AnswerContract`);
- белый список методов API и полей;
- лимиты источников: 250 монет, 365 дней, дата начиная с 1999-01-01.

**Журнал:**

- маскирование ключей.

**Тесты:**

- 40 автотестов pytest, внешние API и модель подменяются;
- эталонный набор из 10 запросов (`tests_data/queries.jsonl`: 7 валидных, 2 двусмысленных, 1 невыполнимый) прогоняется утилитой `tools/replay_queries.py`. Результат — 10 из 10.

| Показатель | Вручную | Автоматизированный (ИИ-агент) |
| --- | --- | --- |
| 1 операция | 10 мин | 1 мин |
| Объем: 100 аналитических операций | 16,7 ч ≈ 10 000 ₽ (600 ₽/ч) | 1,7 ч ≈ 1 000 ₽ + LLM ≈ 20 ₽ + API 0 ₽ |

Вывод: платформа экономит около 90 % времени и около 9 000 ₽ на каждые 100 операций. Дополнительно — единый формат данных и полная история запусков.

## 10. Риски и меры снижения

| Риск | Мера |
| --- | --- |
| Ответ модели не по формату | Строгий контракт; нарушение → блокировка Guardrails |
| Модель пропустила некорректный запрос | Решение принимает политика, модель может только ужесточить |
| Подмена адреса или полей | Только белый список |
| Утечка ключей | `.env` вне git, маскирование в журнале, ключ не попадает в `api_url` |
| Сбой или лимит внешнего API | 502/504 с причиной, запись в аудит |
| Исчерпание 100 запросов exchangerate.host | Внешний вызов только при сборе; заблокированные запросы лимит не тратят |
| Ответ по данным без опоры на записи | Обязательные ссылки на существующие записи |

## 11. Проблема, решение, результат

1. **Проблема:** подготовка таблицы котировок криптовалют и фиатных валют вручную занимает около 10 минут и не оставляет истории.
2. **Решение:** платформа на FastAPI, SQLite и Docker. LLM строит план сбора в строгом JSON, политика качества пропускает только запросы из белого списка, неоднозначные запросы блокируются подсистемой Guardrails, каждая операция фиксируется в аудите.
3. **Результат:** 1 минута на операцию вместо 10, эталонный прогон — 10 из 10, ни одного автоматического сбора по неоднозначному запросу.

## 13. Заключение и регламент приемо-сдаточных испытаний

Платформа реализует сквозной контур: веб-панель → API → SQLite → LLM со строгим JSON-контрактом → политика качества (Guardrails) → журнал аудита.

Регламент испытаний:

1. Развернуть платформу по разделу «Быстрый запуск (Docker)» в README.
2. Выполнить автотесты: `docker compose exec api python -m pytest -q -p no:cacheprovider`. Критерий: 40 из 40.
3. Выполнить эталонный прогон: `docker compose exec api python tools/replay_queries.py --collect`. Критерий: «Совпадений: 10/10», записи сохранены по запросам 1–7, запросы 8–10 заблокированы.
4. В веб-панели пройти три пользовательских сценария из раздела 2.
5. Проверить экспорт JSON и CSV в разделе «Витрина».
6. Проверить раздел «Аудит»: каждая операция присутствует в журнале со статусом, длительностью и причиной.

## 14. Сложности и как решались

- Модель отклоняла корректную дату как «будущую». Решение: в промпт передаётся текущая дата, проверку дат выполняет код.
- Модель возвращала пустой `plan_steps` для заблокированных запросов. Решение: уточнена инструкция, нарушение контракта переводит запрос в блокировку.
- Лимит exchangerate.host — 100 запросов в месяц, котировки к рублю пересчитываются через USD. Решение: один вызов на сбор, планирование источник не вызывает.
- В Windows curl искажает кириллицу, переданную в аргументе команды. Решение: тела запросов вынесены в файлы `docs/requests/*.json`.
