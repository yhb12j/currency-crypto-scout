# Отчёт: Разведчик валют и криптоактивов

## Название проекта

Разведчик валют и криптоактивов — сбор данных из публичных API, витрина и ответы на вопросы по собранным данным.

## Ценность

Аналитику, финансисту или трейдеру регулярно нужны таблицы котировок: топ криптовалют, цены выбранных монет, история цены, курсы валют к рублю. Вручную на это уходит около 10 минут на операцию: открыть сайт, отфильтровать, скопировать, очистить, свести в таблицу.

Сервис принимает запрос на русском языке, строит план и собирает данные из бесплатных публичных API (CoinGecko, exchangerate.host). Данные сохраняются в едином формате и выгружаются в JSON или CSV примерно за 1 минуту. Каждое действие фиксируется в журнале аудита. Сомнительные запросы автоматически не исполняются и передаются на ручную проверку.

## Сценарии пользователя

1. **Ежедневный срез рынка.** Набор «Топ-10 криптовалют», запрос «Собери топ-10 криптовалют по капитализации в долларах и сохрани поля: rank, name, symbol, price, change_24h». Действия: «Спланировать» → «Собрать» → «Скачать CSV». Результат: 10 записей с выбранными полями.
2. **Курсы для расчётов.** Набор «Курсы валют к рублю» (exchangerate.host), запрос «Собери курсы доллара, евро и тенге к рублю на дату 2026-09-01». Результат: 3 записи с курсами на дату.
3. **Неоднозначный запрос.** Запрос «Собери самое важное». Результат: `needs_review = true`, причина и рекомендации в панели, кнопка «Собрать» заблокирована, запись в аудите со статусом `needs_review`.

## Точки доступа API

| Метод | Путь | Вход → выход |
| --- | --- | --- |
| POST | `/datasets` | `{name, source}` → `{status, dataset_id}`; 400 при пустых полях, 422 при неизвестном источнике |
| POST | `/ai/plan_and_collect` | `{query}` → `{plan_steps, api_url, fields_to_keep, confidence, needs_review, reason, hints}` |
| POST | `/datasets/{id}/collect` | `{query}` → `{status, records_saved}`; 404, 422 (ручная проверка), 502/504/500 с записью в аудит |
| GET | `/datasets/{id}/records?limit=` | записи с `created_at`, `dataset_id`, `record_json` |
| GET | `/datasets/{id}/export?format=json\|csv` | файл выгрузки |
| POST | `/datasets/{id}/ask` | `{question}` → ответ со ссылками на записи |
| GET | `/audit/runs`, `/audit/summary`, `/agent_runs` | журнал, сводка, решения ИИ |

## Схема данных

- `datasets(id, created_at, name, source)`
- `records(id, created_at, dataset_id → datasets.id, record_json)`
- `agent_runs(id, created_at, query, plan_json, needs_review, error)`
- `audit_runs(id, created_at, action, input, output, status, error, duration_ms)`

Хранилище — SQLite: в Docker это том `market-data` (`/app/data/market.db`), при локальном запуске — `data/market.db`. На поля наложены CHECK-ограничения (`status ∈ ok|needs_review|error`, `needs_review ∈ 0|1`), добавлены индексы по `dataset_id` и `created_at`.

## ИИ-операция

Модель: gpt-4o-mini через ProxyAPI, `response_format = json_object`.

**Схема JSON** (`PlanContract`, pydantic, `strict=True`):

```json
{
  "plan_steps": ["строка", "... от 1 до 5"],
  "api_url": "строка",
  "fields_to_keep": ["строка"],
  "confidence": "high | medium | low",
  "needs_review": true,
  "reason": "строка"
}
```

**Температура:** 0.2.

**Разделение ролей:**

- политика качества (детерминированный код) разбирает запрос и строит `api_url` и `fields_to_keep` только из белого списка;
- модель формулирует шаги плана и оценивает запрос, но может только ужесточить решение.

**Когда нужна ручная проверка** (`needs_review = true`):

- `confidence = low`;
- запрос двусмысленный: нет объекта или ограничений;
- запрос невыполнимый: закрытые данные, прогноз, рекомендации, нарушены лимиты источника, дата в будущем;
- запрос не соответствует источнику набора;
- модель нарушила JSON-контракт.

В этих случаях сбор не выполняется, причина пишется в `agent_runs.error` и `audit_runs.error`, а в панели показываются блоки «Почему» и «Что сделать».

## Память и контекст

- План сохраняется в `agent_runs`. Сбор повторно использует план для того же запроса и источника, если он построен не более 15 минут назад, и не вызывает модель ещё раз.
- `/datasets/{id}/ask` передаёт модели до 50 последних записей набора. Ответ принимается только со ссылками на существующие `record_id`.

## Контроль качества

**Вход:**

- обязательные поля и длина (`name`, `source` — до 200 символов, `query` и `question` — до 1000);
- источник из списка;
- `limit` от 1 до 500.

**Выход:**

- строгие контракты pydantic для ответов модели (`PlanContract`, `AnswerContract`);
- белый список методов API и полей;
- лимиты источников: 250 монет, 365 дней, дата начиная с 1999-01-01.

**Журнал:**

- маскирование ключей.

**Тесты:**

- 40 автотестов pytest, внешние API и модель подменяются;
- эталонный набор из 10 запросов (`tests_data/queries.jsonl`: 7 корректных, 2 двусмысленных, 1 невыполнимый) прогоняется утилитой `tools/replay_queries.py`. Результат — 10 из 10.

## План внедрения за 1 день

1. Получить ключи ProxyAPI и exchangerate.host и заполнить `.env` (15 мин).
2. Выполнить `docker compose up --build -d` (5–10 мин).
3. Выполнить `docker compose exec api python tools/replay_queries.py --collect` и проверить аудит (5 мин).
4. Создать рабочие наборы данных под задачи команды (30 мин).
5. Провести инструктаж пользователей (30 мин) и наблюдать за разделом «Требует проверки».

## Риски и меры снижения

| Риск | Мера |
| --- | --- |
| Ответ модели не по формату | Строгий контракт; нарушение → ручная проверка |
| Модель пропустила некорректный запрос | Решение принимает политика, модель может только ужесточить |
| Подмена адреса или полей | Только белый список |
| Утечка ключей | `.env` вне git, маскирование в журнале, ключ не попадает в `api_url` |
| Сбой или лимит внешнего API | 502/504 с причиной, запись в аудит |
| Исчерпание 100 запросов exchangerate.host | Внешний вызов только при сборе, ручная проверка не тратит запросы |
| Ответ по данным без опоры на записи | Обязательные ссылки на существующие записи |

## Проблема, решение, результат

1. **Проблема:** подготовка таблицы котировок криптовалют и курсов валют вручную занимает около 10 минут и не оставляет истории.
2. **Решение:** сервис на FastAPI, SQLite и Docker. LLM строит план сбора в строгом JSON, политика качества пропускает только запросы из белого списка, неоднозначные запросы уходят на ручную проверку, каждое действие фиксируется в аудите.
3. **Результат:** 1 минута на операцию вместо 10, эталонный прогон — 10 из 10, ни одного автоматического сбора по неоднозначному запросу.

## Сложности и как решались

- Модель отклоняла корректную дату как «будущую». Решение: в промпт передаётся текущая дата, проверку дат выполняет код.
- Модель возвращала пустой `plan_steps` для ручных проверок. Решение: уточнена инструкция, нарушение контракта переводит запрос в ручную проверку.
- Лимит exchangerate.host — 100 запросов в месяц, кросс-курсы к рублю рассчитываются через USD. Решение: один вызов на сбор, планирование источник не вызывает.
- В Windows curl искажает кириллицу, переданную в аргументе команды. Решение: тела запросов вынесены в файлы `docs/requests/*.json`.
